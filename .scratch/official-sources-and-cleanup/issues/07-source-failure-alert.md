# 07: 來源連續失敗提醒

**What to build:** 同一個官方來源連續兩天 08:00 都失敗時（包括列表抓不到任何文章），發一則 Telegram 提醒，寫出來源名稱、最近一次失敗原因與管理頁連結。恢復前不重發；恢復時不另外通知，下一次故障再重新提醒。

**Blocked by:** 04：管理頁「官方來源」區塊

**Status:** done

- [x] 來源失敗時累計連續失敗次數，成功一次就歸零並清除已提醒狀態
- [x] 次數達到 2 且尚未提醒時建立一則提醒；第三次以後不重發
- [x] 提醒走既有的通知保存與送出機制，失敗只重送同一份；與文章通知的去重互不影響
- [x] 提醒內容含來源名稱、失敗原因、管理頁連結
- [x] 測試以注入時間模擬連續兩天失敗、第三天、恢復後再故障

## 實作紀錄

- 連續失敗次數從 `source_runs` 往回數，成功一次就中斷；不另外在 `source_state` 存計數與已提醒狀態。這樣新來源首次就失敗時不必先建立 `source_state`，也就不會因此跳過初次基準；連續故障超過 30 天、早期紀錄被清掉時也不會重發。
- 剛好第二次失敗時建立一則 `source_alert` 類型的通知（不帶文章），內容含來源名稱、最近一次原因與管理頁連結；第三次以後不重發，恢復不通知，恢復後再故障重新提醒。走既有的保存與送出機制，08:00 排程結束時送出。
- 管理頁失敗狀態顯示連續次數（兩次以上），區塊說明補上提醒規則。
- 驗證：以注入時間模擬連續兩天失敗（第一次送出失敗、下一輪重送同一份）、第三天、恢復、空列表再故障兩次；關閉的來源不檢查也不提醒；提醒不影響文章通知。
