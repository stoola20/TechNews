# 10: 未確認費用作廢，恢復按鈕只在暫停時出現

**What to build:** 管理頁預算區塊的每筆未確認費用都有「作廢」按鈕，必須填說明。作廢的費用不算進月預算，但列在「已作廢」明細，顯示時間、類別、金額與說明。升級時，既有的 X 未確認費用（失敗預留與重讀風險估算）全部作廢。「恢復處理」只在暫停時出現，旁邊顯示暫停原因與按下的效果；預算為 0 而無法恢復時，提示先作廢未確認費用或調整月預算。

**Blocked by:** None (can start immediately)

**Status:** done

- [x] 費用新增 `voided` 狀態；月預算已使用金額與預留檢查都排除 `voided`
- [x] 作廢 API 只接受 `uncertain` 費用且必須附說明，記錄作廢時間與說明
- [x] migration 把既有 `x`、`x-reread-risk` 的 `uncertain` 費用改為作廢並附升級說明；其他類別不動
- [x] 預算區塊：未確認明細有作廢按鈕；新增「已作廢」合計與可展開明細
- [x] 恢復按鈕只在暫停時顯示，附暫停原因與一句說明；未暫停時隱藏
- [x] 預算為 0 時恢復失敗並顯示下一步提示
- [x] 作廢後管理頁重新讀取預算與暫停狀態，不自動恢復

## 實作紀錄

- migration 0017：費用表新增作廢時間與說明欄位；既有 `x`、`x-reread-risk` 的未確認費用改為 `voided`，說明「升級時作廢：X 失敗呼叫的預留或重讀風險估算」，其他類別不動。
- 月預算的已使用金額與預留檢查都排除 `voided`。作廢 API 只接受未確認費用、需要 1–500 字說明；回傳最新預算明細，不自動恢復。
- 預算 API 附本月未確認與已作廢的逐筆明細；X 的未確認費用記下讀取類型、情境，以及是「沒收到回應」還是「收到回應後處理失敗」。
- 管理頁：未確認費用逐筆列出並附「作廢」按鈕（頁內輸入說明）；「已作廢」合計可展開看每筆說明與作廢時間；兩者與 X 失敗呼叫都不放進金額明細表。
- 「恢復處理」只在暫停時出現，附暫停原因與按下的效果；手動暫停時隱藏「暫停全部處理」。剩餘預算為 0 時恢復回 429 並提示先作廢未確認費用或調整月預算。
- 測試在 linkedom 裡執行管理頁腳本，透過同一個 handler 檢查按鈕顯示。
- 驗證：作廢需要說明、只接受未確認；作廢後預算與預留檢查排除、仍是費用暫停直到按恢復；升級 migration 只作廢 X 類；內建瀏覽器實際暫停、恢復，並以合成資料查看未確認與已作廢明細排版。
