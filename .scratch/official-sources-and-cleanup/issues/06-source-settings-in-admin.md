# 06: 來源與主題設定併入管理頁

**What to build:** 原本在手機設定頁的「想收到的內容」與來源清單，搬到官方來源區塊。區塊上方是「想收到的內容」文字框；每個來源那一列有開關；收合的「進階：編輯來源 JSON」可以新增、修改、刪除來源。儲存後下一輪排程生效。關閉的來源不參與發現、不觸發失敗提醒，歷史紀錄保留並顯示「已關閉」。

**Blocked by:** 02：移除舊每日導讀流程；04：管理頁「官方來源」區塊

**Status:** done

- [x] 來源設定每筆新增 `enabled`（預設 true），舊設定讀取時視為開啟
- [x] 儲存設定 API 同時接收想收到的內容與來源清單；驗證規則沿用現有來源驗證，失敗回 400 且原設定不變
- [x] 管理頁文字框、開關、進階 JSON 都能儲存並顯示結果
- [x] 關閉的來源不發現、不寫執行紀錄、不累計失敗；列表顯示「已關閉」
- [x] 官方文章的主題篩選使用新存的「想收到的內容」
- [x] 設定文件改寫成用管理頁設定來源

## 實作紀錄

- 來源設定每筆帶 `enabled`；讀取舊設定時視為開啟，保存時一併寫入並移除舊的 `model_profile`。
- 來源驗證改成中文、指出第幾個來源與哪個欄位（id、name、indexUrl、host、kind、paths、enabled）。
- 新增保存設定 API：同時接收想收到的內容與來源清單，驗證失敗回 400、原設定不變；成功回傳最新的官方來源總覽。總覽附上目前設定，關閉的來源狀態為「已關閉」。
- 發現流程略過關閉的來源，不寫執行紀錄。超過 30 天沒有成功檢查（關閉或故障）的來源重新開始時重新建立基準，避免網址紀錄被清掉後，列表上沒有日期的舊文被當成新文章。
- 管理頁官方來源區塊加入「想收到的內容」文字框、每個來源的開關、收合的「進階：編輯來源 JSON」；文字框有未保存的修改時，重新整理不會覆寫。
- 文件改寫成用管理頁設定來源。
- 驗證：格式錯誤（網域不符、enabled 非布林、空白的想收到的內容）回 400 且設定不變；關閉的來源不發現、不寫紀錄；主題篩選使用新存的內容；關閉 40 天後重新開啟只收最新一篇；內建瀏覽器實際切換開關、保存錯誤 JSON，並查看手機寬度。
