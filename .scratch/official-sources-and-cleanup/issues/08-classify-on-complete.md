# 08: 文章完成就分類，通知附主題

**What to build:** 文章寫成已完成或部分完成後，立刻用 Workers AI Gemma 4 分類，再建立通知。Telegram 完成通知與更新通知的第一行是主題標籤（主要主題，有次要主題時接在後面）。分類失敗時通知照常發出、不附主題，之後由維護排程重試。

**Blocked by:** None (can start immediately)

**Status:** done

- [x] Gemini 寫作完成與 Mac 執行器回報完成，兩條路徑都在建立通知前分類
- [x] 分類提示詞、輸出驗證、手動主題優先的規則不變
- [x] 通知第一行為主題標籤；主題名稱中不能出現在 hashtag 的字元換成底線
- [x] 分類失敗時通知不等待、不附主題，失敗次數與延後重試照現有規則；之後重試成功
- [x] 維護排程的分類步驟保留，處理重試、重新分類全部與未分類的既有文章
- [x] 架構文件更新分類時機

## 實作紀錄

- 分類拆成單篇步驟：Gemini 寫作完成時在處理工作內分類；Mac 執行器回報完成時，在回應後的背景工作裡先分類再送通知。這是新版本的第一次嘗試，不等先前失敗的延後時間。
- 分類提示詞、輸出驗證、手動主題優先與失敗延後規則不變；維護排程的分類步驟保留，處理重試、重新分類全部與尚未分類的既有文章。
- 完成、更新與手動重送的通知第一行是主題標籤（主要在前、次要在後），名稱裡 hashtag 不接受的字元換成底線，例如 `#iOS_Apple_開發`。分類失敗時通知照常發出、不附主題。
- 架構文件新增「分類時機」，設定文件改寫主題分類說明；順手移除設定文件裡殘留的舊 digest 說法。
- 驗證：Gemini 路徑先分類再送出、手動主題不被覆寫且仍附在通知；執行器路徑先分類再通知；分類失敗時通知不附主題，維護排程在延後時間到之前不重試、到期後分類成功，已送通知不重發。
