# 06: 筆記與追問版面實作

**What to build:** 依使用者選定的設計稿實作筆記與追問位置，閱讀文章時不必捲到頁尾輸入。

**Blocked by:** 05：筆記與追問擺放設計稿；04：媒體與說明相鄰、閱讀頁順序

**Status:** done（設計稿 B：閱讀區下方懸浮、可收合的筆記／追問對話框）

- [x] 依選定方案實作桌機與手機
- [x] 筆記自動保存、追問歷史與既有行為不退化
- [x] 鍵盤、focus、窄螢幕無溢位以實際瀏覽器驗證

## 實作紀錄

- `src/learning/page.js`：「我的筆記」與「來源追問」從閱讀區最下方移到 `#dock` 對話框，放在閱讀區之後。收合時一條列有「筆記／追問」分頁（`role=tab`，方向鍵切換）、快速追問輸入框與「展開／收合」按鈕（`aria-expanded`，可見文字加螢幕閱讀器補充「筆記與追問」）。桌機懸浮在閱讀欄下方，展開高度 46vh；手機固定在底部，展開最高 78vh，並隱藏快速追問輸入框。
- 閱讀區底部留白與 `scroll-padding-bottom` 跟著對話框實際高度（`ResizeObserver` 寫入 `--dock-h`），捲到底或用 Tab 移動焦點時，正文與焦點都在對話框上方。
- 快速追問按 Enter 直接用目前範圍送出，同時展開對話框顯示進度；空白時只展開並把焦點移到問題欄。
- Escape：對話框展開時先關閉並把焦點還給展開按鈕，這次不觸發手機版返回列表；焦點在對話框內時也不觸發返回列表。焦點在正文時維持原本的返回列表。
- 沒有開啟文章時只顯示追問分頁，範圍是整個文章庫；之後開啟文章時，若整個文章庫不是使用者自己選的，就恢復成目前文章。
- 手機版按「在原文中標出」「查看媒體證據」時先收合對話框，再捲到原文或媒體。
- 筆記保存失敗或有衝突時，「筆記」分頁出現紅點與螢幕閱讀器文字「需要處理」，收合時也看得到。筆記改回已保存內容時狀態顯示「最後保存」，不再停在「編輯中…」。
- 觸控目標都至少 44px；reduced-motion 下展開動畫與箭頭旋轉都關閉。
- 驗證：`tests/library-ui.test.js` 新增對話框結構與 Escape 順序測試，`npm test` 110 項通過。示範伺服器上用內建瀏覽器操作 1440 與 375 寬：展開／收合、分頁切換與方向鍵、快速追問送出（回答、提問紀錄、「在原文中標出」）、筆記自動保存、切換文章時筆記不互相覆寫、衝突提示、Escape、沒有水平溢位；另用本機 Chrome（playwright-core）重跑同一流程截圖，並確認 reduced-motion。
