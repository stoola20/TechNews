# 分享與官方合併、來源補強及閱讀頁調整

**Status:** ready-for-agent

**使用者：** 單一使用者，自用。需求已逐題確認；tickets 依本規格拆分後直接開發。

## Problem Statement

統一文章庫上線後實際使用兩天，遇到五類問題：

1. 在 X 先看到官方文章並分享貼文後，隔天官方排程又整理同一篇，文章庫出現兩篇內容相同的文章。使用者因此猶豫要不要先分享，但又希望盡快讀到第一手消息。
2. 部分文章長期標示來源缺漏，按「補取缺漏並整理」結果仍一樣。實際成因各不相同：X 長文（`x.com/i/article/...`）未登入無法讀取；沒有 `<article>`／`<main>` 的網頁擷取失敗；外部網頁的頭像、logo 等裝飾圖片被當成媒體，無法取得時也列為缺漏。
3. 搬移前的官方短導讀想改用 Gemini 詳細整理。文字模型設定已是 Gemini，但 Gemini 對沒有媒體的純文字文章仍回傳媒體觀察，驗證失敗三次後停在「需要處理」，畫面仍顯示原本的 Workers AI 模型，看起來像沒換模型。部分舊導讀當初沒保存原文，「只重寫文字」沒有材料可用。
4. 閱讀頁的影片與逐段說明分在兩區，說明還帶著「舊版媒體觀察」字樣；外部網頁的 logo 也被放進媒體區。原始來源夾在教材與媒體之間；筆記與追問在頁面最下方，需要在文章與輸入框之間來回捲動。
5. 手機上按「刪除這篇待回補」沒有反應。按鈕依賴瀏覽器原生 `confirm()`，Telegram 等 App 內建瀏覽器常直接擋掉並視為取消。

## Solution

X 貼文唯一的外部文章連結和文章庫某篇是同一網址時，兩者合併成一篇。先分享後官方只補記收件入口；官方先到、後分享則把貼文加進來源，必要時重寫。既有重複一次合併。

來源取得分層補強：一般網頁先擴大擷取範圍，再用 Browser Rendering；X 長文先實測 X API，取不到時由 Mac 執行器用已登入的瀏覽器 profile 代抓；都失敗時可手動貼上原文。裝飾圖片不收、不算缺漏。

修正 Gemini 純文字驗證，讓逐篇重寫可靠，缺原文時自動重抓官方原文，確認時寫明使用的模型。

閱讀頁讓每個媒體緊接自己的時間點說明，原始來源移到最下方；筆記與追問的位置先出兩份設計稿供選擇。所有確認改為頁面內對話框。

## User Stories

1. 身為使用者，我希望先分享 X 貼文後，官方排程抓到同一篇時不再出現第二篇，以便放心第一時間分享。
2. 身為使用者，我希望官方已整理、之後才分享 X 貼文時，收到既有文章入口，以便不浪費生成費用。
3. 身為使用者，我希望 X 貼文的作者說明與補充併入同一篇文章來源，以便同時看到官方全文與作者脈絡。
4. 身為使用者，我希望只連到單一文章的貼文才合併，以便整理型貼文不被誤併進某一篇。
5. 身為使用者，我希望既有重複文章一次合併並保留筆記與已讀，以便清掉現有雜訊。
6. 身為使用者，我希望合併後舊連結仍能開啟，以便 Telegram 舊通知不失效。
7. 身為使用者，我希望 X 長文能被取得或明確告知取得方式，以便不長期停在缺漏。
8. 身為使用者，我希望自動取得失敗時可以手動貼上原文，以便自己補齊來源。
9. 身為使用者，我希望沒有標準正文標記的網頁也能擷取，以便常見的模型或工具頁不被列為缺漏。
10. 身為使用者，我希望頭像、logo、小圖示不被當作來源媒體，以便媒體區只有有意義的內容。
11. 身為使用者，我希望裝飾圖片取不到時不算缺漏，以便缺漏提示只反映真正缺少的內容。
12. 身為使用者，我希望純文字文章用 Gemini 重寫不再失敗，以便把舊導讀改成詳細教材。
13. 身為使用者，我希望重寫沒有原文的舊導讀時自動重抓官方原文，以便不用先手動補缺漏。
14. 身為使用者，我希望確認重寫前看到會使用哪個模型，以便知道實際由誰整理。
15. 身為使用者，我希望每支影片下方緊接它自己的時間點與內容，以便邊看邊對照。
16. 身為使用者，我希望媒體說明只顯示秒數與內容、不帶多餘標籤，以便版面乾淨。
17. 身為使用者，我希望原始來源與片段放在頁面最下方，以便閱讀時不被打斷。
18. 身為使用者，我希望先比較筆記與追問的兩種擺放設計，以便選出不必來回捲動的版面。
19. 身為使用者，我希望在手機內建瀏覽器中確認刪除、補缺漏、重寫與重送通知都有反應，以便從 Telegram 開啟時也能操作。

## Implementation Decisions

### 合併 X 貼文與外部文章

- 合併條件：X 貼文來源中**唯一**的非 X 外部文章連結，正規化後與另一篇文章的網址相同。有兩個以上外部文章連結的貼文不合併。X 內部連結（引用、父貼文、其他貼文）不計入外部文章連結。
- 合併後只保留一篇文章，來源包含 X 貼文、作者補充與外部全文。另一篇的收件入口、筆記與已讀狀態併入；被併掉的文章 ID 透過既有別名表導向保留的文章。
- 先分享、官方後到：官方發現同網址的文章已被合併文章涵蓋時，只新增官方收件紀錄，不建立新文章、不生成、不通知。
- 官方先到、後分享：分享的 X 貼文併入官方文章，回覆既有文章入口。既有版本是舊短導讀時，用目前文字模型重寫成詳細教材並發更新通知；已是詳細版時不重寫，只回覆連結。
- 兩篇都在處理中時，以先建立的文章為保留對象，另一篇停止並導向。
- 既有重複由一次性合併處理：保留較完整的一篇（詳細版優先於舊短導讀；同為詳細版時保留含 X 貼文來源者）。合併不呼叫模型、不讀外部來源、不發通知，且可重複執行不產生副作用。
- 合併判斷在外部連結取得後進行，不額外呼叫 X 或其他付費 API。

### 來源取得補強

- 一般網頁：沒有 `<article>`／`<main>` 時，從 `<body>` 擷取，先移除 script、style、nav、header、footer、aside、button。仍無法取得有效正文時，若有 Browser Rendering binding，再以渲染後 HTML 擷取一次。失敗仍記錄缺漏與原因。
- 裝飾圖片：外部網頁圖片排除 SVG、網址路徑含 logo／avatar／icon／branding／emoji、`width`／`height` 屬性或網址尺寸參數標示不超過 200px、位於 header／nav／footer／aside 內者。被排除的圖片不登記為媒體，也不列入缺漏。X 貼文自身的媒體照舊全部保留。
- X 長文：先以一次真實 X API 讀取確認貼文欄位能否取得長文全文；能取得則在讀取貼文時直接帶入長文正文，作為該貼文來源的一部分。
- X 長文無法經 API 取得時，建立 Mac 代抓工作：Mac 執行器用一個已登入 X 的專用 Playwright 瀏覽器 profile 開啟長文頁，擷取正文後回報雲端，雲端保存為外部來源並以目前文字模型重新整理。只在文章有 X 長文缺漏時建立工作，頻率低；不保存 X 登入 cookie 到雲端。Mac 離線時工作等待，不視為失敗。
- 手動貼上原文：缺漏來源可在文章頁貼上原文，保存為該網址的來源並標示為使用者提供，之後重新整理。只接受目前列為缺漏的網址。

### 重寫可靠性

- Gemini 回傳的媒體觀察，若文章沒有任何媒體，直接忽略觀察而非視為錯誤。
- 「只重寫文字」遇到沒有保存原文的舊官方導讀時，先依官方來源設定重抓公開原文再排入整理；重抓失敗則如實列為缺漏。
- 重寫、補缺漏的確認對話框寫出目前的文字模型名稱。
- 不提供批次升級全部舊導讀；不在單篇提供模型選擇，仍由管理頁設定決定。

### 閱讀頁

- 由上到下為：標題、狀態與操作 → 教材 → 媒體與時間點 → 舊版本 → 原始來源與片段。
- 每個媒體（影片或圖片）下方緊接屬於它的說明，每行只顯示時間點按鈕（若有）與內容，不加「舊版媒體觀察」「畫面」等標籤。Gemini 觀察新增對應單一媒體的識別；既有只對應到貼文的觀察，依所屬貼文分組放在該貼文最後一個媒體之下。
- 筆記與追問位置先產出兩份可比較的設計稿（放 `docs/previews/`），附桌機與手機版：
  - A：桌機三欄，左側列表與右側筆記／追問欄都可收合或展開。
  - B：畫面下方懸浮、可收合的筆記／追問對話框。
  使用者選定後才實作。
- 所有確認改為頁面內對話框，支援鍵盤操作與焦點返回，不依賴 `window.confirm()`。

### 流程與公開 repo

- 本 repo 公開。commit、PR、測試與文件只放通用需求與合成資料，不寫入私人文章 ID、網址、帳號或操作紀錄。

## Testing Decisions

- 合併：唯一外連相符時兩個方向都合併；多個外連不合併；先分享後官方不生成、不通知；官方舊導讀後分享會重寫並發更新通知；詳細版後分享只回覆；舊 ID 經別名開啟；一次性合併冪等且不呼叫外部 API。
- 來源：無 `<article>`／`<main>` 網頁可擷取；Browser Rendering 後備只在第一次擷取失敗時呼叫；裝飾圖片不登記、不成缺漏；X 長文欄位解析使用合成回應；Mac 代抓工作以公開 API 驗證領取與回報、離線等待；手動貼上只接受缺漏網址。
- 重寫：純文字 Gemini 回傳觀察不再失敗；舊導讀缺原文時會重抓；確認文字含模型名稱。
- 閱讀頁：以內建瀏覽器實際操作驗證媒體與說明相鄰、順序正確、頁內確認對話框在手機寬度可用。
- 真實 X API 實測只記錄欄位是否可用的結論，不保存貼文內容或帳號資訊。

## Out of Scope

- 批次升級全部舊導讀、單篇模型選擇。
- 依文章主題或相似度判斷重複（只比對網址）。
- 多外連整理型貼文的拆分或部分合併。
- 在雲端保存 X 登入狀態、以 computer use 操作桌面取得來源。
- 部署與正式環境 migration；完成後另行決定。
