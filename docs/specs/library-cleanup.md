# 文章庫介面整理：頁首、篩選、主題色與文章工具列

**Status:** ready-for-agent

**使用者：** 單一使用者，自用。需求已逐題確認，視覺方向以設計稿 `docs/previews/library-cleanup.html` 的方案 A 為準。本規格建立在「文章篩選、精讀問答、間隔複習與保留文章 RAG」（`docs/specs/curated-study.md`）與文章頁啟動並行化（branch `perf/parallel-page-load`）之上。

## Problem Statement

文章庫 `/learning` 的功能一路加上來，畫面上的控制項越來越多，閱讀時反而被干擾。

1. **頁首有用不到的輸入框。** 「貼上網址＋加入文章庫」佔了頁首中央，但實際加文章都用 Telegram 的分享功能傳給 bot。
2. **側邊欄頂端疊了五層控制項。** 依序是入口列（待決定 N 篇、今日複習、每週回顧）、搜尋、未讀／排序／管理篩選、五個檢視分頁、主題 chips。列表本身被擠到很下面，也不知道哪些按鈕常用。
3. **文章頂端有七個按鈕。** 保留、常用、刪除、標記未讀、補取缺漏並整理、只重寫文字、重送通知全部並排。後三個是維運動作，正常閱讀時用不到。
4. **主題色被誤認成未讀。** 列表每篇標題前有一個主題色圓點。未讀其實是用粗體表示，但常見的閱讀 App（例如 iOS 郵件）用圓點表示未讀，所以經常誤以為還沒讀完。
5. **主題 chips 要左右滑。** 主題有 7 個以上，chips 只排一行、橫向捲動；側邊欄寬度又不能調整，看不到全部主題。

## Solution

- **頁首**：移除加入連結表單。搜尋移到頁首中央（桌機），按 `/` 或 ⌘K／Ctrl+K 聚焦；手機版頁首只放放大鏡圖示，點了才展開搜尋列。「今日複習（題數）」與「每週回顧」移到頁首右側。
- **側邊欄篩選**：頂端只留三段式分頁「保留／★ 常用／待決定 N」與一個「篩選」按鈕。其他條件（範圍：全部或最近刪除、只看未讀、排序、收件入口、處理狀態）收進「篩選」選單；有套用條件時按鈕顯示數字。逐篇篩選模式的入口移到「待決定」分頁的列表頂端。
- **主題色**：列表不再顯示主題色。chips 與文章頂端的主題標籤改用「淡色底」：主題色 12% 的淡底、深色文字；選取時改成實心主題色、白字。chips 換行全部顯示，不再橫向捲動。
- **未讀**：列表的未讀文章在標題前顯示單一藍色圓點，標題維持粗體；已讀文章沒有圓點。
- **側邊欄寬度**：桌機版的列表與閱讀區之間有拖曳把手，寬度記在這台裝置；雙擊把手還原預設寬度。
- **文章工具列**：左邊是「保留／常用／刪除」，右邊是「標記未讀」、「⋯」選單與「專注」。「補取缺漏並整理」只在文章有缺漏或錯誤時出現，而且放在缺漏提示旁邊。「只重寫文字」與「重送通知」收進「⋯」選單，條件不符時不顯示。

## User Stories

### 頁首

1. 身為使用者，我希望頁首不再有貼網址的欄位，以便頁首只留下我會用到的東西。
2. 身為使用者，我希望搜尋列在頁首中央，以便不論捲到列表哪裡都能直接搜尋。
3. 身為使用者，我希望按 `/` 或 ⌘K／Ctrl+K 就能聚焦搜尋，以便不用滑鼠。
4. 身為使用者，我希望手機版頁首只放放大鏡圖示，點了才展開搜尋列，以便手機上保留閱讀空間。
5. 身為使用者，我希望頁首右側看得到「今日複習」與當天題數，以及「每週回顧」，以便從任何畫面進入。

### 側邊欄篩選

6. 身為使用者，我希望側邊欄頂端只有「保留／★ 常用／待決定」三段式分頁，待決定附篇數，以便一眼看到最常切換的檢視。
7. 身為使用者，我希望其他條件都在「篩選」選單裡，以便側邊欄頂端保持乾淨。
8. 身為使用者，我希望「篩選」按鈕在有套用條件時顯示數字，以便知道列表正被過濾。
9. 身為使用者，我希望選單裡有「清除篩選」，以便一次回到預設檢視。
10. 身為使用者，我希望在選單裡選「全部」或「最近刪除」時，三段式分頁都不顯示選取，以便清楚知道目前不在這三個檢視裡。
11. 身為使用者，我希望在「待決定」分頁的列表頂端有逐篇篩選的入口，以便從待決定清單直接開始篩選。
12. 身為使用者，我希望篩選條件仍保存在網址中，以便重新整理或返回時維持同一個檢視。

### 列表、主題色與未讀

13. 身為使用者，我希望列表只用藍色圓點表示未讀，以便不再把主題色誤認成未讀。
14. 身為使用者，我希望主題名稱仍以灰字出現在每篇的資訊列，以便知道文章屬於哪個主題。
15. 身為使用者，我希望主題 chips 有淡淡的主題色底，選取時變成實心主題色，以便用顏色快速辨認主題。
16. 身為使用者，我希望自訂任何主題色時，chip 上的文字都清楚可讀，以便不必挑選特定顏色。
17. 身為使用者，我希望主題 chips 換行全部顯示，以便不用左右滑動。
18. 身為使用者，我希望文章頂端的主題標籤和 chips 長得一樣，以便同一個主題在各處看起來一致。

### 側邊欄寬度

19. 身為使用者，我希望在桌機上拖曳列表與閱讀區之間的分隔線來調整列表寬度，以便依螢幕與內容調整。
20. 身為使用者，我希望這台裝置記住調整後的寬度，以便下次打開還是同樣寬。
21. 身為使用者，我希望雙擊分隔線就還原預設寬度，以便調壞時能快速回復。
22. 身為使用者，我希望也能用鍵盤調整寬度，以便不用滑鼠也能操作。

### 文章工具列

23. 身為使用者，我希望文章頂端左邊是保留、常用、刪除，以便最常做的篩選動作最好按。
24. 身為使用者，我希望右邊只有標記未讀、「⋯」選單與專注，以便工具列保持精簡。
25. 身為使用者，我希望「補取缺漏並整理」只在文章有缺漏或錯誤時，出現在缺漏提示旁邊，以便正常文章看不到維運按鈕，有問題時又知道怎麼處理。
26. 身為使用者，我希望「只重寫文字」與「重送通知」放在「⋯」選單裡，條件不符時不顯示，以便需要時還找得到。
27. 身為使用者，我希望「⋯」選單可以用鍵盤開關，按 Esc 關閉並把焦點還給按鈕，以便操作和其他對話框一致。

## Implementation Decisions

### 頁首

- 移除 `#collect-form` 與它的送出處理。`POST /learning/api/collect` 保留不動，之後要加回網站入口或用指令呼叫都還能用。
- 頁首改成三欄：品牌、置中搜尋（最寬 560px）、右側導覽（今日複習與題數徽章、每週回顧、執行狀態、管理、登出）。
- 搜尋框沿用 `#search` 與 `#search-form` 的 id 與行為，只搬到頁首。`/` 的既有快捷鍵保留，再加 ⌘K／Ctrl+K。
- 寬度 959px 以下：搜尋框收成放大鏡按鈕（`aria-expanded`）；點了在頁首下方展開整列搜尋並聚焦，搜尋框沒有內容時按 Esc 或失焦會收起。
- 「今日複習」沒有題目時，題數徽章不顯示，連結仍在。點擊行為沿用現在 `renderEntries` 的模式切換。

### 側邊欄篩選

- 三段式分頁對應 `view.triage` 的 `kept`、`starred`、`pending`；`all` 與 `deleted` 從「篩選」選單的「範圍」選擇，這時三段都不顯示選取。
- 「篩選」選單是一個 popover：範圍、只看未讀、排序、收件入口、處理狀態、清除篩選、完成。選單內的變更立即套用並寫進網址，與現在的行為相同。
- 按鈕上的數字 = 範圍不是預設分頁 + 只看未讀 + 排序不是預設 + 收件入口 + 處理狀態。主題 chip 與搜尋不計入，因為它們本身就看得到。
- 選單開啟時 Esc 或點選單外面會關閉，焦點回到「篩選」按鈕。
- 移除 `#entry-bar`。「待決定」分頁的列表頂端顯示「逐篇篩選（N 篇）」按鈕，N 為 0 時不顯示。

### 主題色與列表

- 列表項目移除 `.topic-dot`，改成未讀圓點：未讀用 `--unread`（藍色，與白底的對比至少 3:1，非文字元素的標準），已讀不佔位也不顯示。粗體規則不變。
- chips 與 `.topic-tag` 用 CSS 變數 `--c` 帶入主題色，背景 `color-mix(in srgb, var(--c) 12%, #fff)`，邊框 28%，文字用 `--ink`；選取時背景與邊框為 `--c`、文字白色。「全部」的選取色用 `--ink`，「未分類」用中性灰。
- chips 改成 `flex-wrap: wrap`，移除橫向捲動。
- 白字放在實心主題色上不一定有 4.5:1 的對比。選取時加粗文字；並在管理頁的主題設定旁說明「顏色太淺時，選取狀態的白字可能不清楚」，不自動改色。

### 側邊欄寬度

- 960px 以上的版面改成三欄格線：`var(--side) 6px minmax(0,1fr)`，中間是 `role="separator"`、`aria-orientation="vertical"`、可以聚焦的把手。
- 拖曳範圍 280–560px，預設 340px。寬度存在 `localStorage` 的 `technews-side-width`；讀寫失敗時用預設值，不報錯。
- 鍵盤：把手聚焦時，左右方向鍵每次調整 16px，Home 回到預設。雙擊同樣回到預設。
- 專注模式與手機版不顯示把手。

### 文章工具列

- `triageBar` 與 `actions` 合併成一列：左邊是保留／常用／刪除，右邊是標記未讀、「⋯」、專注。`#focus-toggle` 從 `.reader-bar` 移到工具列；`.reader-bar` 只留手機版的返回按鈕。
- 「⋯」選單只放符合條件的動作：「只重寫文字」（狀態為 ready、partial、needs_attention、error）與「重送通知」（ready 或 partial 且為詳細版）。兩者都不符合時不顯示「⋯」。確認對話框沿用現有文字。
- 「補取缺漏並整理」移到「來源與處理提醒」區塊的右側；只在有缺漏或 `last_error` 時出現，條件與現在相同（不含等待回補）。
- 等待回補的文章維持現在的「開始整理這篇」主要按鈕，位置在工具列右側取代「⋯」。
- 專注模式隱藏「⋯」與補取按鈕，與現在隱藏 `.manage` 的規則一致。

## Testing Decisions

- 這次只改前端頁面，沒有 API 或資料庫變更。測試檢查頁面 HTML 與腳本的外部結構，沿用 `tests/library-ui.test.js` 的做法：頁面與管理頁腳本可解析、不使用原生 `confirm()`、關鍵元素存在或已移除。
- 要測的結構：
  - 頁首沒有 `#collect-form`；`#search` 在 `header.top` 內；頁首有今日複習與每週回顧連結。
  - 側邊欄沒有 `#entry-bar` 與 `#manage-toggle`；有三段式分頁與 `aria-haspopup` 的「篩選」按鈕。
  - 列表項目不再輸出 `topic-dot`；chips 樣式含 `flex-wrap:wrap`，不含 `overflow-x:auto`。
  - 把手的 `role="separator"` 與 `localStorage` 鍵名。
  - 工具列的「⋯」按鈕有 `aria-haspopup` 與 `aria-expanded`。
- UI 實際操作：用示範伺服器與內建瀏覽器，在 1280px 與 375px 操作搜尋（含快捷鍵與手機展開）、三段分頁、篩選選單與清除、網址還原、主題 chip、未讀圓點、拖曳與鍵盤調寬、「⋯」選單、補取按鈕的出現條件、專注模式；確認手機寬度沒有橫向捲動，主控台沒有錯誤。
- 正式站沒有新的驗收項目：這次沒有後端變更。部署後只確認兩頁可以開啟。

## Out of Scope

- 收件 API、Telegram 收件流程與管理頁版面。
- 篩選模式、今日複習、每週回顧頁面本身的內容。
- 深色模式。
- 主題色自動調整以符合對比標準。
- 列表每列的快速操作按鈕。

## Further Notes

- **合併順序：** 開發分支 `claude/library-cleanup` 從 `perf/parallel-page-load` 切出，因為兩邊都改 `page.js` 的啟動流程。實作 PR 在效能 PR 合併後 rebase 到 main。
- **為什麼收掉網站加入入口但保留 API：** 使用者實際只用 Telegram 分享；API 保留讓 README 的快速開始仍能用指令驗證部署，之後若要加回網站入口，只需要前端。
- **為什麼用淡色底而不是彩色文字：** 主題色可以在管理頁任意自訂。淡色底配深色文字對任何顏色都能維持文字對比；彩色文字遇到黃、淺灰等顏色時對比不足，加深後顏色又彼此難分。
