## 收件異常與修復證據

Telegram 曾回報 webhook `404 Not Found`，有 3 則待送更新；D1 尚無目標文章與收件回覆。收件程式使用允許的數字 chat ID 與 webhook secret 驗證，不依個人傳送者名稱決定是否接受頻道貼文。

將同一份新 webhook secret 同步至 Worker 與 Telegram 後，不含文章連結的驗證更新得到 HTTP 200，待送數量降為 0，原分享自動收件。未丟棄待送更新、未要求重送來源。維護時必須同步兩邊的 secret；`setWebhook` 回應成功本身不能證明 Worker 已接受驗證碼。

## 媒體連結誤報修正

貼文 URL 的 `/video/1` 後綴曾被當作未取得外連，造成 3 筆假缺漏；對應的主貼文、作者補充與影片均已取得。修正後按 post ID 核對 `/video/N`、`/photo/N` 與原貼文，尚未取得的其他貼文仍保留缺漏。回歸驗證覆蓋已取得主文與作者補充，以及尚未取得的另一篇貼文。

本篇已校正為 `ready`、缺漏為空，保留 3 個可用來源、3 支完成處理的影片與原教材。只移除已核對的假缺漏，保留原始模型輸入 fingerprint 與通知紀錄，未再次呼叫 Gemini。
