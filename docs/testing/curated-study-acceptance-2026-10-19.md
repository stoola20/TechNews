## 已完成的程式驗證

### 自動測試

`cd cloud-digest && npm test`：29 個測試檔、180 個測試全部通過。`npm run format:check` 通過。

測試縫隙沿用最高層：`createLearningHandler` 的 `fetch`、`scheduled`，以及 Mac 執行器的 `runner/*` 端點。資料庫是記憶體 SQLite，依序套用全部 migration；時間用注入的 `now()`；Telegram、Gemini 與 Google 搜尋用記錄呼叫的假網路；embedding 用決定性的假模型（同義詞與中英對照落在相近的向量）；Vectorize 用記憶體實作。

### 外部介面查核（查核日 2026-10-19）

- Cloudflare 模型目錄（`cloudflare-docs` repo 的 `workers-ai-models/embeddinggemma-300m.json`）：輸入 `text` 可為字串或陣列，陣列最多 100 筆；輸出 `{ shape, data }`。Cloudflare changelog 記載輸出 768 維。
- Vectorize 限制文件：最多 1536 維、向量 ID 最長 64 bytes、Workers upsert 每批 1000 筆、不回傳 metadata 時 topK 最多 100、Free 方案儲存 5,000,000 維度。
- `@google/genai` 型別定義：`groundingMetadata.webSearchQueries` 與 `groundingChunks[].web.{uri,title}`。
- Gemini 3 可同時使用 Google 搜尋與結構化輸出、每月前 5,000 次搜尋免費、之後每 1,000 次 US$14、一個請求可能有多次搜尋：來自搜尋結果引用的官方文件與價格頁內容。這次環境連不到 ai.google.dev，**沒有直接開啟官方頁面**。
- EmbeddingGemma 的查詢與文件前綴：沿用規格記載的 Google 模型卡格式；這次環境連不到模型卡，**沒有重新查核**。

## 還沒有在真實環境驗收

以下項目只有模擬測試，需要使用者在正式環境操作後另存紀錄：

1. **Migration**：`0018`–`0024` 套用到正式 D1；既有文章全部變成待決定、已可閱讀的文章標記不過期，篩選模式能逐篇處理舊文章。
2. **Vectorize 與 Workers AI**：建立 `technews-library`（512 維、cosine）；EmbeddingGemma 的實際回應形狀、前綴效果與 neurons 用量；Vectorize 寫入後幾分鐘內可查到；刪除向量後不再出現。
3. **檢索品質與門檻**：語意 0.42、相似文章 0.55、相關文章 0.5 都是初始值，要用真實保留文章調整，調整時同步更新規格與 `retrieval.js` 註解。
4. **Telegram 按鈕**：`setWebhook` 加入 `callback_query` 後，在通知頻道按下按鈕會更新文章庫、提示文字與按鈕；復原；未允許對話被忽略。
5. **Gemini 出題、批改與網路查證**：真實文章的題目品質（考解釋與套用、不考名詞）、批改回饋與出處；`gemini-3.8-flash` 同時使用 Google 搜尋與 JSON schema 是否穩定（社群回報 3.x Flash 偶爾回傳不完整的 JSON，程式會標示查證失敗）；搜尋次數與帳單是否一致。
6. **Mac 執行器 1.2.0**：真實 Ollama Gemma 依區段格式輸出題目與批改的通過率、context 是否足夠放下整篇片段。
7. **iPhone Safari**：捲到結尾自動標已讀、專注模式與篩選模式在實機上的操作感。
8. **D1 用量**：保留文章與複習題累積後，列表、全庫追問與維護排程的每日讀取量仍在 Free 額度內。
