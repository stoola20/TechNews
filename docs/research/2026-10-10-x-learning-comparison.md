## A 建議：自建雲端流程，再逐步加入 Mac mini {span=3}

```callout ok 你的偏好已明確
你重視文章品質與來源完整，也願意自行開發。
因此，方案 ② 最適合作為長期主線。
Grok Bot 用來比較取得與整理能力。
Mac mini 到貨後，先加入保存與媒體處理。
```

先取得足夠證據，再比較模型的教材品質。
模型無法補回沒有取得的作者補充或影片畫面。
三個方案都能出錯；自建流程的優勢是能追查與重試。

**比較假設**：每月 300 個收藏，適量作者補充，少量影片。
第一階段採手動分享與 X 書籤同步。
月費 US$30 是討論假設，尚未確認為硬上限。
所有金額為 USD，不含稅金、人工及已購硬體。
架構與工時是提案，品質和速度尚未實測。

## B 三個方案，主要差在哪裡？

| 比較項目 | ① Grok Bot＋文章庫 | ② 自建雲端流程 | ③ Mac mini 混合流程 |
|---|---|---|---|
| 最適合 | 先體驗產出，減少串接 | 長期使用，重視可查核 | 本機保存與媒體處理 |
| 我的定位 | 比較對象、短期驗證 | **長期主線首選** | 到貨後的擴充方向 |
| 文章品質 | 同一批素材實測 | 相同證據可換模型比較 | 本機與雲端品質需比較 |
| 來源完整度 | 同步、補充與匯出待驗證 | 可記錄缺漏並重試 | 同方案 ②；媒體可本機重做 |
| 硬體 | 現有手機、電腦 | 現有手機、電腦；不需 GPU | 已購 M6／32 GB＋備份空間 |
| 必要服務 | X、Grok Bot、自己的文章庫 | X API、Cloudflare、生成模型 | X API、雲端收件、本機服務、補強模型 |
| 資料保存 | 另存文章庫；匯出能力需測 | 雲端 D1＋R2，可另備份 | 原始資料主要本機，文章可同步 |
| 月費估算 | 新訂閱約 US$25 起，另加用量 | **US$20–40**；成本例約 US$25–40 | **US$18–35＋電費、備份**；依下方假設 |
| 初版工時 | 驗證版 2–5 人日；正式整合另估 | 基本同步與文章庫 10–20 人日 | 從零建置 15–30 人日 |
| 維護負擔 | 較少；仍需監看任務 | 中等；授權、來源與重試 | 較高；另加本機服務與復原 |
| 主機離線 | 雲端 Bot 繼續執行 | 雲端流程繼續執行 | 收件保留，處理等主機恢復 |
| 更換模型 | 受產品整合方式影響 | 可更換生成與解析模型 | 可更換本機與雲端模型 |

工時是工程估算，沒有包含完整 iOS App。
三者都依賴 X 取得管道，無法承諾完整取得每個討論串。

## C ① Grok Bot：先驗證學習體驗

```flow TB
(X 書籤或 App 分享) -> Grok Bot
Grok Bot -> 取得與整理
取得與整理 -> 匯出文章與證據: 待驗證
匯出文章與證據 -> [(自己的文章庫)]
自己的文章庫 -> 閱讀與追問
```

**優點**：帳號整合、雲端電腦與排程已有現成能力。
最快能確認這類教材是否值得每天閱讀。

**缺點**：書籤增量、作者補充與自動匯出仍待驗證。
只保存生成文章，會讓查錯與追問更困難。
自己的文章庫與追問仍需建置。

**硬體**：現有手機或電腦即可。
工作在雲端執行，不需 Mac mini 常開。

**依賴**：X、Grok Bot／Cursor 與自己的保存位置。
Telegram 通知可另接。

**成本**：Cursor Pro 約 US$20／月。
另抓 US$5 作為輕量文章庫預算。
超額用量與 X credits 另計。
已有合資格訂閱時，可能不需新訂閱。
週額度是否足夠，仍要實測。

官方確認 X 整合包含書籤工具。
公開標記 @bot 的入口遇影片或 GIF 不接單。
此限制不能套用到所有 Grok 媒體能力。
[X 整合](https://x.ai/news/grok-bot-and-x) · [入口限制](https://docs.x.ai/grok-bot/tag-on-x)

## D ② 自建雲端：讓證據與寫作都能檢查

```flow TB
(Telegram 分享或 X 書籤) -> Worker 收件與排程
Worker 收件與排程 -> X API 取得來源
X API 取得來源 -> [(D1 證據與任務)]
D1 證據與任務 -> Gemini 媒體解析
Gemini 媒體解析 -> 教材生成
教材生成 -> [(D1 與 R2 文章庫)]
D1 與 R2 文章庫 -> 閱讀與來源追問
```

**優點**：可分別檢查取得、解析與寫作結果。
可用相同證據比較模型，並保存處理紀錄。

**缺點**：需自建授權、分頁、去重與重試。
影片取得和討論串完整度仍受來源限制。

**硬體**：無常開主機或 GPU 需求。
重型轉檔另安排運算資源；不塞進 Worker。

**依賴**：X API、Cloudflare Workers、D1、R2。
Gemini 3.8 Flash 作媒體解析候選。
Gemini 或 Claude Sonnet 5.5 作寫作候選。
解析與寫作可用同一模型，不必用兩家服務。
xAI X Search 可選用補強，另計費。
這是起始配置，不是已驗證的品質排名。

**成本**：規劃 US$20–40／月。
下方成本例約 US$25–40。
實際費用取決於來源讀取、影片和追問量。

現有 TechNews 可重用 Worker、D1 和 Telegram。
X 同步、媒體解析及文章庫追問仍是新增工作。

## E ③ Mac mini：先接管保存與媒體工作

```flow TB
(雲端收件) -> [(雲端任務佇列)]
雲端任務佇列 -> Mac mini 主動領取
Mac mini 主動領取 -> 保存與媒體前處理
保存與媒體前處理 -> 本機或雲端模型
本機或雲端模型 -> [(本機證據與文章庫)]
本機證據與文章庫 -> 同步完成文章
```

**優點**：原始資料可本機保存，媒體可反覆處理。
也能用已購硬體比較本機模型。

**缺點**：需維護服務、模型、磁碟與備份。
主機離線會延後處理。
送到雲端模型的內容仍會離開本機。

**硬體**：已購 Mac mini M6／32 GB。
另備持續網路連線與獨立備份。
先試 Gemma 4 12B Q4，再測較大模型。
官方估計 12B Q4 權重載入約 6.7 GB。
上下文、系統與執行環境還需額外記憶體。
M6 速度與相容性尚未實測。

**依賴**：X API、雲端收件、本機模型與媒體工具。
必要時使用 Gemini／Claude 補強。

**成本**：US$18–35＋電費與備份。
此估算假設本機完成 70% 教材，雲端完成 30%。
這是成本情境，尚未驗證能達到所需品質。
若更多文章改由雲端重寫，費用接近方案 ②。

[Gemma 記憶體估算](https://ai.google.dev/gemma/docs/core)

## F 每月費用怎麼算？

以下是方案 ② 的估算例，不是報價。
書籤讀取包含重讀的舊收藏。
300 篇教材各使用 6,000 input＋2,000 output tokens。

| 項目 | 計算假設 | 月費 USD |
|---|---|---:|
| 自用書籤 | 1,500 個符合 Owned Reads 的回傳資源 × 0.001 | 1.50 |
| 作者補充與引用 | 900 個一般貼文讀取資源 × 0.005 | 4.50 |
| Sonnet 5.5 教材 | 180 萬 input × 2／百萬＋60 萬 output × 10／百萬 | 9.60 |
| Workers | 付費方案基本費 | 5.00 |
| 其他預留 | 媒體、儲存、重試與追問；未量測 | 4–19 |
| **合計** | 不含人工、稅金與硬體 | **24.60–39.60** |

```callout info 本機能省多少？
上述 300 篇的 Sonnet 純生成費是 US$9.60。
若本機完成 70%，剩下的雲端生成費約 US$2.88。
省下約 US$6.72，尚未扣除電費與維護。
X 取得費不會因本機推論而消失。
```

每天讀回 100 個書籤，30 天就是 3,000 個資源。
符合 Owned Reads 時，該部分約 US$3。
作者補充與其他資源另計。
不要只按新增的 300 個收藏估算取得費。

同樣文字量改用 Gemini 3.8 Flash，純生成費約 US$3.60。
官方列出的 2027-01-01 起價格會使它增為 US$7.20。
兩者皆未包含額外推理、媒體與工具用量。
R2 標準儲存單價為 US$0.015／GB-month。
另有操作費與免費額度。

Grok Bot 的訂閱與用量另算。
不要把上述 API 成本直接套入它的週額度。

## G 品質優先：用一個例子看處理差異

**假設案例**：你收藏一篇工具示範。
作者貼了影片，又在回覆補上設定條件。
第三則作者回覆指出某個模式仍有限制。

| 處理階段 | 需要保存或檢查什麼？ | 漏掉時的後果 |
|---|---|---|
| 取得來源 | 主貼文、作者續寫、引用與外部文章 | 把有限定條件的示範寫成通用能力 |
| 理解影片 | 操作步驟、關鍵畫面與時間點 | 只翻譯旁白，讀者仍無法操作 |
| 編寫教材 | 背景、機制、例子、限制與來源 | 文章流暢，但技術主張錯誤 |
| 支援追問 | 回答連回原文與媒體證據 | 後續回答繼續放大先前的錯誤 |

Gemini 可理解影片；預設取樣仍可能漏快速畫面。
重要段落需重查或增加取樣。
API 取得也不能保證每個討論串完整。

**下一步提案**：用 30 個真實收藏完成小型驗證。

1. 涵蓋文字、作者補充、圖片、影片與外部文章。
2. 比較 Grok Bot 與自建管道取得的證據。
3. 用相同證據比較生成模型。
4. 記錄缺漏、技術錯誤、修正時間與總費用。

先建立完整文章庫與基本搜尋。
Telegram 提供導讀與連結，教材不受訊息長度限制。
Jev、語意搜尋和完整 iOS App 留待需求明確後加入。
Mac mini 先接管保存與媒體處理，再測正式寫作。
